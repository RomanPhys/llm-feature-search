# LLM-признаки из транзакций: польза от модели или от перебора

Проект к заданию отбора на кафедру Математики ИИ (ФПМИ МФТИ и Сбер), задача 10. Идея в том, чтобы LLM
предлагала признаки из истории банковских транзакций для градиентного бустинга. Здесь я проверяю, откуда
берётся прирост качества: от самой LLM или просто от того, что перебрано больше кандидатов.

## Идея

Признаки задаются грамматикой, а не произвольным кодом. Каждый признак это нормированный агрегат по
транзакциям за последние w дней, прошедшим фильтр.

* Агрегаты: count, sum, mean, std, max, дни с последней операции, активные дни, число разных MCC.
* Окна: 7, 30, 90, 180 дней или вся история. Окно всегда заканчивается в момент прогноза, поэтому
  утечка из будущего невозможна по построению.
* Фильтры: группа MCC, список кодов или значение категориального поля.
* Нормировки: доля от того же агрегата без фильтра или отношение к тому же агрегату в более длинном окне.

## Что сравнивается

У всех источников кандидатов одинаковые данные и разбиение, один стартовый набор F0, одно число
кандидатов, одна модель и одно правило отбора. Отличается только то, кто выбирает кандидатов.

| источник | что знает |
|---|---|
| random_raw | грамматику, отдельные частые коды MCC и значения других категориальных полей |
| random_groups | то же, но вместо отдельных кодов MCC смысловые группы, которые придумала LLM |
| llm | грамматику и группы, и сама выбирает признаки |

Разница random_groups и random_raw показывает вклад групп, разница llm и random_groups вклад выбора кандидатов.

Каждый источник я проверяю с двумя правилами отбора. Правило naive принимает признак, если прирост
ROC-AUC на валидации больше нуля, так делает CAAFE. Правило strict принимает его, только если прирост
значим по парному бутстрэпу после поправки Холма. Финальная проверка одна, на отложенном тесте, с парным
бутстрэпом против F0. Разрыв между приростом на валидации и на тесте показывает, насколько отбор переобучился.

## Предложения LLM

Предложения в llm/features_churn.json я получил одним запросом к LLM (Claude) с промптом из
llm/prompt.md. Модели передавались только описание задачи и схема полей, без транзакций и без меток.
Предложения, которые не проходят проверку грамматики или ссылаются на коды, которых нет в данных,
отбрасываются автоматически. В ноутбуке есть ячейка, которая запрашивает предложения у любой LLM
через OpenAI-совместимый API, например у локальной модели в vLLM.

## Результаты

### Запуск 1: слабый F0, 3 сида

Rosbank, 5000 клиентов с меткой (490 513 транзакций, доля оттока 0.553), разбиение 60/20/20.
F0 из 15 общих агрегатов даёт на тесте ROC-AUC 0.702. Прирост ROC-AUC на тесте к F0:

| источник | правило strict | правило naive |
|---|---|---|
| llm | 2 признака, +0.037 [+0.017; +0.058] | 10 признаков, +0.035 |
| random_raw | значимый признак в 1 из 3 сидов (+0.062) | от +0.002 до +0.079 |
| random_groups | 0 из 3 | от +0.012 до +0.055 |

Оба признака LLM про пополнения карты: давность последнего пополнения и тренд суммы пополнений.
Это понятный сигнал оттока, зарплата перестала приходить на эту карту.

Что я из этого вынес и исправил:
* у random_groups не было фильтров по типу операции, а сигнал сидел именно там, поэтому сравнение было
  нечестным; теперь у обоих случайных пулов одинаковые фильтры, кроме описания MCC;
* F0 был слабым и не знал о пополнениях вообще; теперь по умолчанию F0 содержит доли операций по типам
  и частым MCC, и признаку надо добавить что-то сверх этого;
* при мягком правиле разброс между сидами огромный, поэтому сидов теперь 10, а главная величина это доля
  запусков, где найден значимый на тесте набор.

## Ограничения

* Синтетические данные (make_synthetic) нужны только для проверки кода. Сигнал в них заложен вручную,
  поэтому выводы о пользе LLM по ним делать нельзя.
* Один датасет, одно разбиение, один запрос к LLM без обратной связи. Бюджет уравнен по числу кандидатов,
  а не по времени.
* В Rosbank метки оттока есть примерно у 5 тыс. клиентов, поэтому интервалы широкие, и отсутствие
  значимой разницы не доказывает, что её нет вообще. Для ориентира: в статье EAFD на Rosbank CoLES даёт
  ROC-AUC 0.835, Featuretools поверх CoLES 0.863, CAAFE 0.870, EAFD 0.872.
